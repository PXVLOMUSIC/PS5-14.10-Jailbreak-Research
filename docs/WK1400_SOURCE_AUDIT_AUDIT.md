## Critical contradictions

### 1. IsoHeap claim is WRONG (line 25)

**Doc says:**
> "IsoHeap isolation confirmed. Both `CanvasRenderingContext2D` and `OffscreenCanvasRenderingContext2D` use `WTF_MAKE_ISO_ALLOCATED`, preventing cross-type heap replacement."

**Source evidence:**
- `IsoMalloc.h:31-36`: When `!USE(ISO_MALLOC)` (PS5 config), `WTF_MAKE_ISO_ALLOCATED(name)` → `WTF_MAKE_FAST_ALLOCATED`.
- `BPlatform.h:341`: `BENABLE_LIBPAS` is enabled on PS5, but `USE(ISO_MALLOC)` is OFF.
- Therefore, `WTF_MAKE_ISO_ALLOCATED` degrades to standard FastMalloc on PS5.

**Verdict:** ❌ The doc's claim is **false** for PS5. IsoHeap is OFF, not ON. This is the opposite of what the doc states. This is the single most important error in the audit.

**Impact:** The audit concludes "0 exploitable bugs" partly because IsoHeap was thought to prevent cross-type reclaim. But IsoHeap is OFF, which is exactly why CVE-2026-43720 is exploitable (same-type reclaim works).

### 2. Guard count is wrong (line 17)

**Doc says:**
> "The 11 `PLATFORM(PLAYSTATION)` guards are logging-only"

**Source evidence:**
- 47 guard lines found across 31 files (not 11).
- 2 guards have security relevance: `VM.cpp:395` (disableFreezingForTesting → JSC Config unfrozen) and `BAssert.h:35` (release assertions OFF).
- Other guards are platform adaptations (allocator, mutex, MAT logging).

**Verdict:** ⚠️ Count is wrong (11 vs 47) and characterization is wrong ("all logging-only" — 2 have security impact).

### 3. OffscreenCanvas claim (line 25)

**Doc says:**
> "OffscreenCanvasRenderingContext2D uses WTF_MAKE_ISO_ALLOCATED"

**Source evidence:**
- `OffscreenCanvas` is not available on PS5 14.10 (confirmed by device fingerprint: `offscreen=false`).
- The guard `#if ENABLE(OFFSCREEN_CANVAS)` is not enabled in PS5 config.
- The IsoHeap claim is moot since the API is absent.

**Verdict:** ⚠️ The API is not available on PS5; the IsoHeap claim is doubly wrong.

## Critical impact

The WK1400_SOURCE_AUDIT.md audit concluded **"0 exploitable bugs"** partly because:
1. IsoHeap was thought to be ON (it's OFF).
2. Guards were thought to be "logging-only" (2 have security impact).

This audit is **the reason CVE-2026-43720 was initially dismissed** and had to be retracted. The retraction is documented in `DEAD_ENDS.md` ("Canvas getContext() UAF — RETRACTED").
